## CLI 规范化重构（用户要求整理 MiniGPT 目录）

背景：用户觉得根目录乱，最终选择"重构 CLI 到规范布局"。查证 packaging.python.org 后确认：平铺根脚本非最佳实践，权威推荐 src-layout + console_scripts entry point。

约束发现（关键，勿踩坑）：
- 300+ 处引用根目录脚本名，分布在 README(20)/MANUAL(246)/CONSTRUCTION(16)、web/js、setup.ps1、dist 包、bundle 模板。
- 测试直接 `import chat`/`from chat import Conversation`/`from visualize import iter_trace`/`import prepare` 等，访问内部符号。
- `test_evaluate_eos.py` 用 `mock.patch.object(evaluate, "_load_bundle")` 后调 `evaluate.main()` —— shim 必须让 patch 与 main 指向同一模块。
- 大量测试按文件名调用脚本：`ROOT/"prepare.py"`、`dashboard.py --help` 等，顶层脚本绝不能删。
- `test_docs.py` 有 README 行数上限 120 的守卫。
- dist 同步白名单 `RUNTIME_FILES` 不含 CLI，无需改 bundle.py。
- 非 git 仓库，无版本回滚能力。

采用方案（零破坏）：
- 顶层 10 个脚本全部原地保留（唯一实现层，零改动）。
- 新增 `minigpt/cli/` 包，10 个别名模块用 importlib 从根加载同名脚本并 `sys.modules[__name__] = _impl`，使 `minigpt.cli.X is X` 为同一对象；末尾加 `if __name__ == "__main__": raise SystemExit(_impl.main())` 支持 `python -m`。
- 新增 `pyproject.toml`：setuptools，10 条 `minigpt-*` console_scripts 指向 `minigpt.cli.X:main`，`py-modules` 列顶层脚本，`packages.find` 含 `minigpt*`。
- README 工作区结构一节原地补充规范入口说明（不增行，保持 120 行）。

验证：基线 501 项 OK(skipped=2)；重构后两次全量均 501 项 OK(skipped=2)；`mock.patch`、对象同一性、`-m` 入口、pyproject 入口解析全部验证通过。
